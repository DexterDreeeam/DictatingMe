🧩 关键约束

  • MainWindow ⇄ HudWindow 互斥：由 Window Manager 依据 State Machine 广播的状态切换，同一时刻只有一个可见
  • 因果链：EvokeModel 检测到唤醒词 → State Machine → 才触发 DictationModel 加载（① → ②）→ 同时才允许 Audio Ring Buffer 开始缓冲（③）。三者都不会在唤醒词检测之前发生，Audio Capture 本身持续采集麦克风音频，但只有 State Machine 授权后音频才会被写入缓冲区
  • 点击托盘图标 = 向 State Machine 发出"打开 MainWindow 请求"，效果等价于一次 dismiss
  • EvokeModel 与 DictationModel 互斥运行：前者仅 Listening 态激活，后者仅 Loading/Dictating 态激活
  • Streaming Output 不使用剪贴板，直接模拟键盘输入，只追加不回退
  • Runtime 与 UI 同进程（Tauri），无需跨进程 IPC

🎨 颜色语义

黄：可被唤醒（EvokeModel 监听中）
绿：正在记录输入（缓冲录音 或 流式转写）
灰：无响应状态（不监听也不记录）

🔄 状态一览

  • Configure：MainWindow 打开中，全局锁定（灰，不分首页/二级页）
  • Listening：默认待机监听唤醒词（黄灯）
  • Loading：加载ASR模型 + 无缝缓冲录音（绿灯，录音已开始）
  • Dictating：流式转写 + 打字（绿灯）
  • Unloading：收尾清理，不再记录（灰），回到 Listening

⚠️ 设计取舍

  • Configure↔Listening 双向：打开MainWindow进入，关闭MainWindow退出
  • 非 Listening 态收到"打开MainWindow"请求时，自动先走完 Unloading→Listening，再进入 Configure，无需二次操作
  • Dictating 无静音超时，只能靠任意键鼠 dismiss（或打开MainWindow请求）结束
  • Unloading 会丢弃尚未转换完成的内容，不等模型跑完
  • Loading→Dictating：缓冲音频是第一批处理数据，无缝衔接不丢帧
  • EvokeModel 仅 Listening 态运行，与 Dictating 天然互斥
1
Listening
用户说出唤醒词
麦克风音频持续流向 EvokeModel（<20MB 常驻模型）
2
Listening → Loading
EvokeModel 检测到唤醒词
State Machine 切换到 Loading；HUD 沿用黄灯（过渡态）
3
Loading
异步加载 DictationModel + 同步开始录音缓冲
本地 ONNX 千问 ASR 模型加载中；麦克风音频同时写入 Ring Buffer，不等待模型加载完成
4
Loading → Dictating
DictationModel 加载完成
State Machine 切换到 Dictating；HUD 变绿灯
5
Dictating
缓冲音频无缝喂入，不丢帧
Ring Buffer 中 Loading 阶段录制的音频作为第一批数据喂给模型，随后无缝接续实时音频流
6
Dictating · 循环
流式识别 → 增量打字
DictationModel 产出当前完整识别文本 → Text Diff 对比上一次结果，仅取新增后缀 → Text Injector 模拟键盘打字到当前系统焦点（不用剪贴板，不做回退修正）
7
Dictating → Unloading
用户任意键盘/鼠标操作（dismiss）
全局键鼠监听捕获事件 → State Machine 立即切换到 Unloading
8
Unloading
停止喂音频，丢弃未转换内容，卸载模型
不等待模型处理完最后一段；DictationModel 立即卸载释放内存
9
Unloading
写入 History
本次记录（音频 + 最终文本 + 时间戳）写入 History Store，FIFO 队列超过 20 条自动淘汰最旧一条
10
Unloading → Listening
清理完成，回到待机
State Machine 回到 Listening，HUD 变黄灯，等待下一次唤醒
↺ 循环回到步骤 1，等待下一次唤醒

🎨 颜色语义

黄：唤醒词识别阶段（步骤1-2，EvokeModel监听中）
绿：声音采集/转换阶段（步骤3-6，录音缓冲或流式转写）
灰：不检测声音阶段（步骤7-10，收尾清理）

📌 时序要点

  • 唤醒→Loading 是异步的：模型加载与录音缓冲同时开始
  • Dictating 每一轮都是"全量假设 → diff → 追加打字"，不是逐字符流
  • Dismiss 后立即中断，未转换内容直接丢弃，不等模型收尾
  • History 写入发生在 Unloading 阶段，回到 Listening 之前
